产品 A · 随时访问

测试看板（建议入口 /dashboard）

给老板 / PM / Dev / QC 打开即看「现在怎样」，不依赖当天是否发信。

  • 测试执行计划：用例设计进度、测试评审日期/结论、测试执行排期（及是否按排期）
  • 当前测试执行进度：相对排期的完成度、Story/用例执行现状
  • Bug 修复进度：未关总量、P0/P1、Fixed Rate、关键未关列表
  • 测试风险点：带 Owner 的 Open 风险清单（实时维护）

特点：实时/近实时 · 可刷新 · 可深挖明细 · 不强制「今日结论」

产品 B · 按日节点发出

测试日报（优化现有 /report）

给收件人在「当日节点」读「今天相对计划偏了多少、风险申报、怎么拉回来」。

  • 当日节点分析：健康灯 + 今日结论 + 需管理层关注
  • 总进度 vs 测试计划：计划/实际/偏差（快慢）
  • 风险点申报：当日仍 Open / 新增 / 关闭的风险（含 Owner 与动作）
  • 分析与应对：为何偏离、如何回归健康、复查点
  • 精简进度摘要 + Bug 摘要（详情链到看板）

特点：日切快照 · 强制人工判断 · 行动导向 · 邮件可读

一句话分工

看板 = 现在的状态机；日报 = 今天的决策纪要。
老板随时打开看板看进度与风险；下班读日报看偏差、申报与应对。明细与矩阵优先放看板，日报只保留摘要。

数据流（草案）

测试计划基线
Sprint 初冻结 → MS 执行 + 飞书 Story/Bug → 风险清单
人工维护 · 双端共用 → 看板（实时读） → 日报（日切 + 人工结论）

字段归属

信息 测试看板 测试日报 说明
测试执行计划 主阵地：用例设计 / 评审日期 / 执行排期 引用计划对比「是否按排期」 开发 Ready 节奏可作辅助，计划表以测试侧活动为主
执行进度（现状） 主阵地（含明细） 摘要 + 异常置顶 日报不再堆 13 列全表
计划 vs 实现偏差 可展示 Ahead/Behind 主阵地（当日节点） 回答老板第 1 点
Bug 修复进度 主阵地（摘要+列表） 一行摘要 + P0/P1 矩阵默认只在看板
风险点 全量 Open 清单 申报视角（新增/仍在/关闭） 同一风险库；Blocked≠自动风险
分析与应对 可选「当前应对」 每日必填 回答老板第 3 点
访问方式 Web 随时打开 邮件 + 预览页 看板不替代发信

建议落地顺序

阶段 内容
v1 ① 风险清单数据模型（看板/日报共用）② 日报 v2 邮件结构（结论/偏差/申报/应对 + 瘦表）③ 看板只读页：计划摘要、进度、Bug、风险
